# 通用写作规范

## 目标

产出表达准确、简洁、自然，且在目标领域内专业、自洽的文章。

## 1. 写作

- 先结合写作背景和上下文，确定读者、用途、内容核心范围和不涉及的范围这四个核心。
- 读者应明确文档面向谁；用途应说明文档帮助读者完成什么任务，对读者有什么意义。
- 内容核心范围应基于读者，提取并适度抽象和概括文档的要点。
- 不涉及的范围应明确与用途相关、容易被误认为包含在内的内容边界。
- 在文档开头的 YAML frontmatter 中填写“读者”“用途”“内容核心范围”和“不涉及的范围”，内容应具体到当前文档。
- Agent 专用或对 frontmatter 格式有固定要求的文档（如 SKILL.md、AGENTS.md），以及作为仓库首页展示的 README.md，不写上述四个核心 frontmatter。
- 优先使用准确的领域术语，不滥用术语。
- 句子按语义自然断句，段落保持逻辑连贯。
- 删除空话、套话和没有信息增量的表述。
- 区分事实、推断、假设、建议和个人观点。
- 复杂概念先准确解释，必要时再使用类比。
- 不强制套用固定章节结构或句式。
- 不为了压缩篇幅而省略必要前提和限定条件。

## 2. 修订

- 修订始终围绕当前文档的四个核心展开。
- 修订前理解目标章节及其关联上下文。
- 根据语义影响范围决定修订粒度。
- 允许重写段落、章节乃至全文。
- 不为维持最小 Diff 而保留不合理的旧结构。
- 保留有效事实、重要约束、证据和必要例外。
- 删除同一文档内的冗余时，先标出疑似重复，再比较其语义、限定条件和叙述目的，确认没有独立作用后再删除。

## 3. 跨文档修订

- 事实一致性：同一个事实，在不同文档中不能相互矛盾；表达可以因上下文场景而不同。
- 重复判断：
  - 允许不同文档保留必要的共同事实。
  - 判断重复时考虑语义、限定条件和叙述目的。
  - 不以文本相似度直接判定冗余。
- 叙述独立性：
  - 每篇文档都应包含完成自身阅读任务所需的信息。
  - 不得为了去除冗余损害文章自包含性和连贯性。
- 跨文档去除冗余时，先识别疑似重复，说明判定理由、各自用途及拟处理方式；随后必须中断相关修订，等待真实人类操作者的显式授权，获得授权后再按获准方案修订。

这里的“真实人类操作者的显式授权”，须由真实人类操作者针对具体变更或方案明确作出。多 Agent 场景中，主 Agent、子 Agent 或其他 Agent 的同意、自我确认及工具返回的批准状态均不能代替该授权；沉默、等待超时或未提出异议也不构成授权。已有授权明确覆盖当前变更时，无须重复请求。

## 4. 修订方法与工具

- 使用 [Markdown 审计入口](Markdown-审计入口.md) 中的 Gate 校验格式质量。
- 任何可能改变句子含义、术语、指代对象、适用条件或论证关系的修订，都必须先理解原文上下文。
- 禁止仅通过无上下文理解的全局搜索替换或正则表达式完成修订。
- 批量修订前确认适用范围和例外。
- 修订后审阅 Diff，检查是否存在误删，不得仅凭 Diff 验收质量。
- 修订后通读受影响的上下文，确认含义变化符合修订目的，未引入非预期的指代、条件或论证变化。

## 5. 最终审校

- 将最终文档作为独立文章从头阅读。
- 检查跨章节矛盾、重复论证和术语漂移。
- 检查代词指代、前提衔接和段落过渡。
- 保留必要的解释性重复，不追求零重复。
- 格式检查不能代替语义审校。
