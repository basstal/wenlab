# 当前状态文档写作规范

## 目标

当前状态文档以当前有效的事实、方案和约束为主体，如项目详情、开发 SOP、当前架构设计等。
需要保留历史信息时，应明确标注，避免读者将其误认为当前状态。

## 1. 写作

- 遵循 [通用写作规范](通用写作规范.md) 第 1 节的全部要求。
- 把重点放在段落开头。先写结论或动作，再写理由与证据。
- 每段只回答一个问题，或围绕一个中心主旨展开。
- 用稳定名称指代同一对象。
- 需要写明功能或命令的地方，先写适用条件，再写功能或命令，让不适用的读者及时跳过。
- 用编号表达有先后关系的操作。
- 按语义换行，按观点分段。允许在完整句子或分句后插入源码软换行，便于逐行审阅；段落之间仍留空行。

## 2. 修订

- 遵循 [通用写作规范](通用写作规范.md) 第 2 节的全部要求。
- 事实、方案或约束发生变化时，应删除旧表述，用完整的新表述重写。
- 事实、方案或约束被移除时，删除相关表述。
- 修订正文内容，不通过追加纠正句代替完整修订。
- 有保留价值的历史信息应明确适用时间或历史属性，并与当前状态区分。

## 3. 跨文档修订

- 遵循 [通用写作规范](通用写作规范.md) 第 3 节的全部要求。

## 4. 修订方法与工具

- 遵循 [通用写作规范](通用写作规范.md) 第 4 节的全部要求。

## 5. 最终审校

- 遵循 [通用写作规范](通用写作规范.md) 第 5 节的全部要求。
- 检查当前有效的事实、方案和约束是否明确，是否残留失效表述。
- 检查历史信息是否有清晰标注，是否可能被误读为当前状态；不以文档修订时间代替时效性核验。
