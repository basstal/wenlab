# 当前状态文档写作规范

## 目标

当前状态文档以当前有效的事实、方案和约束为主体，如项目详情、简历、开发 SOP、当前架构设计等。需要保留历史信息时，应明确标注，避免读者将其误认为当前状态。

本文以 [通用写作规范](通用写作规范.md) 为基准，补充结构与时效性要求。以下只列出需要补充的章节，编号对应通用规范；未列出的章节直接适用通用写作规范。

## 1. 写作

- 把重点放在段落开头。先写结论或动作，再写理由与证据。
- 每段只回答一个问题，或围绕一个中心主旨展开。
- 用稳定名称指代同一对象。
- 明确谁执行动作。读者据此知道自己承担哪一步。
- 先写适用条件，再写指令。让不适用的读者及时跳过。
- 用编号表达有先后关系的操作。
- 按语义换行，按观点分段。允许在完整句子或分句后插入源码软换行，便于逐行审阅；段落之间仍留空行。

## 2. 修订

- 事实、方案或约束发生变化时，更新对应的当前表述，不在正文中累积互相冲突的新旧说法。
- 有保留价值的历史信息应明确适用时间或历史属性，并与当前状态区分。
- 无法确认是否仍然有效的信息应标为待核验，不直接当作当前事实。

## 5. 最终审校

- 检查当前有效的事实、方案和约束是否明确，是否残留失效表述。
- 检查历史信息是否有清晰标注，是否可能被误读为当前状态；不以文档修改时间代替时效性核验。
