# 中文技术写作语义审校清单

本文整理阮一峰《[中文技术文档的写作规范](https://github.com/ruanyf/document-style-guide)》中需要按语义判断的规则。这些规则无法由 [Markdown 审计入口](Markdown-审计入口.md) 中的 Gate 机械检查，审阅文档时应逐条核对。可以机械检查的规则已写入 Gate，本文不再重复。

本文与 [通用写作规范](通用写作规范.md) 配合使用：通用写作规范规定文档定位与修订方法，本文列出句子和用词层面的具体核对项。

## 句子

| 规则                               | 反例                                 | 改写或核对要点                         |
| ---------------------------------- | ------------------------------------ | -------------------------------------- |
| 尽量使用简单句和并列句，避免复合句 | 那个昨天生病的人没有参加会议。       | 他昨天生病了，没有参加会议。           |
| 同一个意思，尽量用肯定句表达       | 请确认没有接通装置的电源。           | 请确认装置的电源已关闭。               |
| 避免双重否定                       | 没有删除权限的用户，不能删除此文件。 | 用户必须拥有删除权限，才能删除此文件。 |

## 写作风格

| 规则                                                                               | 反例                                                                   | 改写或核对要点                                                               |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 尽量使用主动语态，不用被动语态                                                     | 假如此软件尚未被安装，……                                               | 假如尚未安装这个软件，……                                                     |
| 不使用非正式的语言风格                                                             | 这个功能真是酷毙了，太给力了！                                         | 这个功能显著提升了处理速度。                                                 |
| 不使用冷僻、生造或文言词语，使用现代汉语的常用表达                                 | 这是唯二的快速启动方法。                                               | 这是仅有的两种快速启动方法。                                                 |
| 正确使用“的”“地”“得”：形容词加“的”修饰名词，副词加“地”修饰动词，动词加“得”引出补语 | 她开心的笑了。                                                         | 她开心地笑了。                                                               |
| 代词（如“其”“该”“此”“这”）的指代必须明确，只有一种理解                             | 从管理系统可以监视中继系统和受其直接控制的分配系统。                   | 从管理系统可以监视两个系统：中继系统和受中继系统直接控制的分配系统。         |
| 名词前不堆叠过多的形容词                                                           | 此设备的使用必须在接受过本公司举办的正式的设备培训的技师的指导下进行。 | 此设备必须在技师的指导下使用，且指导技师必须接受过本公司举办的正式设备培训。 |

## 英文处理

| 规则                                                                    | 反例                                     | 改写或核对要点                                                             |
| ----------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| 英文原文使用复数时，译成中文后还原为单数                                | 存储在随机存取存储器（RAMs）里的信息     | 存储在随机存取存储器（RAM）里的信息                                        |
| 英文书名或电影名改用中文表达时，引号改为书名号                          | 他发表了一篇名为“航空业的未来”的文章。   | 他发表了一篇名为《航空业的未来》的文章。                                   |
| 英文词汇第一次出现时，在括号中给出中文标注；此后可直接使用英文缩写      | IOC 负责组织奥运会。                     | IOC（International Olympic Committee，国际奥林匹克委员会）负责组织奥运会。 |
| 专有名词每个词的首字母大写，非专有名词不大写。Gate 只检查五个英文品牌名 | the Online Transaction Processing system | the online transaction processing system                                   |

## 段落

| 规则                                                                           | 反例                           | 改写或核对要点                                              |
| ------------------------------------------------------------------------------ | ------------------------------ | ----------------------------------------------------------- |
| 一个段落只有一个主题，或一个中心句                                             | —                              | 一段讲了两件事时，拆成两段。                                |
| 中心句放在段首，概述全段内容；后面的句子为中心句服务                           | —                              | 先写结论，再写理由与证据。                                  |
| 段落长度不超过七行，最好不超过四行                                             | —                              | 行数随显示宽度变化，Gate 无法统计，按阅读时的实际版面判断。 |
| 段落使用陈述和肯定语气，避免感叹语气                                           | —                              | 把感叹句改为陈述句。                                        |
| 引用第三方内容时注明出处；全篇转载时，在开头显著位置注明作者和出处，并链接原文 | 引用他人观点，但没有说明来源。 | 在引文后注明作者和来源。                                    |
| 使用外部图片时，在图片下方或文末标明来源                                       | 插入外部图片，但没有说明来源。 | 在图片下方注明“图片来自维基百科”。                          |

## 数值

| 规则                                                                           | 反例                                         | 改写或核对要点                           |
| ------------------------------------------------------------------------------ | -------------------------------------------- | ---------------------------------------- |
| 增加时，“增加了”表示增量，“增加到”表示定量；减少时，“降低了”与“降低到”同样区分 | 价格从 1 元涨到 2 元，写成“价格增加了两倍”。 | 价格增加到过去的两倍，或价格增加了一倍。 |

## 标点

| 规则                                                                                                             | 反例                                            | 改写或核对要点                                       |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------- |
| 句子内部的并列词用顿号分隔，即使并列词是英文                                                                     | 我最欣赏的公司有 Google, Facebook, 腾讯和百度。 | 我最欣赏的公司有 Google、Facebook、腾讯和百度。      |
| 并列词的最后一项，尽量用“和”连接                                                                                 | 我最欣赏的公司有 Google、Facebook、腾讯、百度。 | 我最欣赏的公司有 Google、Facebook、腾讯和百度。      |
| 分号用于复句内部并列分句之间的停顿                                                                               | —                                               | 核对分号两侧是否为并列分句。                         |
| 冒号用在需要解释的词语后，引出解释和说明                                                                         | —                                               | 请确认以下几项内容：时间、地点、活动名称和来宾数量。 |
| 尽量避免使用感叹号，用平静的语气叙述。Gate 只检查连用的感叹号                                                    | 这个功能太好用了！                              | 这个功能简化了配置步骤。                             |
| 连接号与破折号按用途区分：两个名词的复合用连字符“-”，进一步解释用破折号“——”。Gate 只能发现可疑写法，无法判断用途 | 氧化——还原反应                                  | 氧化-还原反应                                        |

## 路径

| 规则                                                                                     | 反例                                                                        | 改写或核对要点                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件和目录引用以相对路径为第一优先级，适用于正文、链接、命令示例和配置示例               | 项目内文件写成 `C:\Users\name\project\docs\guide.md`。                      | 能用相对路径准确表达时，改为 `docs/guide.md` 等写法；结合使用位置确定基准目录，避免照搬作者机器上的路径。                                                                                                  |
| 必须使用本地绝对路径时，在上下文中说明例外原因和适用环境；常见用户目录及路径环境变量除外 | 只写“配置文件位于 `/etc/app/config`”，未说明环境和为何使用该位置。          | 固定系统位置、工具强制要求绝对路径、故障记录或教学反例等，需说明为何必须保留绝对路径，并交代操作系统及相关环境；常见用户目录和路径环境变量按下一条处理。例外原因可以在段落或章节中统一说明，无须逐次重复。 |
| 按上下文识别文件系统路径、命令、命令开关和 API 路由，不按斜杠形式统一分类                | 看到 `/build` 就判定为命令开关，看到 `/api/users` 就判定为 Linux 绝对路径。 | 结合所属工具、语法位置和操作对象判断：`/build` 可能是交互命令、开关或目录；`GET /api/users` 中的是 API 路由；`/usr/bin/env` 可以是通过绝对路径调用的可执行文件。命令中的路径参数也需单独判断。             |
| 上下文不足时，先补充用途与环境，再判断是否需要改写                                       | 仅因字符串以 `/` 开头，就删除前导斜杠。                                     | 确认其实际含义后再修改。命令、开关和 API 路由按各自语法保留；本地文件系统路径按相对路径优先和绝对路径例外规则处理。                                                                                        |
