# wenlab Vale 术语与路径规则调查及处理方案

调查日期：2026-10-24。仓库：[basstal/wenlab](https://gitlab.home.arpa/basstal/wenlab)。调查基线：`598e097f81ae0102959d073228c20989b08fc702`。

本文交付调查和处理方案。方案已于 2026-10-24 实施，修改内容与实测结果见第 7 节；第 2 节至第 6 节保留调查时的依据和方案要求。调查时核对了远端代码、配置、使用说明、测试代码及官方资料；当时的环境 PATH 中未找到 Vale，真实工具回归与性能基准在实施阶段完成。

## 1. 建议采用的方案

将两项需求分开落实：

1. 清理 Vale 术语规则：移除无条件的“登陆 → 登录”；“帐户 → 账户”也从通用强制规则中移除，除非项目明确限定其适用语境。保留已经约定的品牌写法，暂不迁移给 CSpell。
2. 增加路径检查：用 Vale 的 `existence` 正则规则发现文档源码中的绝对路径写法；在 rumdl 中启用 MD057，检查相对文件链接，并对以 `/` 开头的链接报警。保留 lychee 的本地、锚点与在线检查。

两类检查均只报告问题，不自动替换词语或路径。绝对路径的修复方式取决于文档位置、命令工作目录和系统约束，不能简单删除盘符或前导斜线。

## 3. 问题一：清理会误导的术语映射

### 3.1 逐项处理

| 当前映射                    | 建议               | 理由及边界                                                                           |
| --------------------------- | ------------------ | ------------------------------------------------------------------------------------ |
| `Github` → `GitHub`         | 保留               | 正文品牌规范明确；当前规则不覆盖全部小写或其他变体                                   |
| `NodeJS` → `Node.js`        | 保留               | 统一品牌形式，包含标点差异                                                           |
| `Powershell` → `PowerShell` | 保留               | 正文品牌规范；不得改写合法的命令和标识符                                             |
| `Typescript` → `TypeScript` | 保留               | 正文品牌规范                                                                         |
| `Javascript` → `JavaScript` | 保留               | 正文品牌规范                                                                         |
| 帐户 → 账户                 | 从通用强制映射移除 | 无上下文规则可能干扰引用、产品原文、字段名和历史用法；如确需统一，应单独说明适用范围 |
| 登陆 → 登录                 | 移除               | “台风登陆”“登陆作战”合法；账号操作语境中的错用交给语义审校                           |

这里的“移除”指删除检查映射，不是批量改写仓库正文。审校人员仍应发现“登陆账号”等具体语境中的用词问题。

### 3.2 不同时迁移到 CSpell

CSpell 支持 `caseSensitive`，但实际结果还受词典内容、分词和多词典叠加影响，不能只开启一个开关就认定与 Vale 完全等价。当前 CSpell 未显式开启大小写检查，此次保留品牌规则，避免清理中文误报时顺带改变另一项覆盖。[CSpell 大小写说明](https://cspell.org/docs/case-sensitive)

Vale 的 `substitution` 是匹配与推荐写法的关联，不会理解“登陆”在句中的语义。正则能增加形式条件，不能保证语义正确。[substitution 官方说明](https://docs.vale.sh/checks/substitution)

## 4. 问题二：用 Vale 检查绝对路径

### 4.1 明确规则适用对象

默认约束可随仓库迁移的项目文档：引用仓库内文件时使用相对路径，不把作者机器上的盘符、用户目录或共享盘位置写成通用操作前提。

以下情况需要区分，不应一律要求改成相对路径：

- 仓库文件链接：优先相对当前 Markdown 文件解析。
- 命令参数中的项目路径：相对文档明确声明的命令工作目录解析。
- 固定系统路径：例如系统配置、安装位置，可能必须使用绝对路径。
- 教学反例、错误日志、外部原文：允许保留必要的原始路径，采用最小范围例外。

<!-- vale Wenlab.AbsolutePaths = NO -->`/docs/a.md` 是根相对链接，`C:\Users\name\a.md` 是 Windows 文件系统绝对路径，`/etc/example.conf` 是 Unix 文件系统绝对路径<!-- vale Wenlab.AbsolutePaths = YES -->；政策可以同时限制，但解析含义不同。`~/project`、`$HOME/project` 等属于依赖用户环境的写法，可后续单独治理，不应在报告中误称已被本次绝对路径规则完整覆盖。

### 4.2 规则类型与扫描范围

新增 `.wenlab/styles/Wenlab/AbsolutePaths.yml`，使用 `extends: existence`、`level: error`，不使用 `substitution`。

建议采用 `scope: raw` 扫描原始 Markdown，覆盖正文、链接目标、图片地址、引用式链接定义、行内代码和代码块。普通正文规则无法保证覆盖这些位置。代价是必须明确允许系统路径与教学反例的例外，不能依靠默认跳过代码来隐藏路径问题。

官方支持在 `existence` 中使用正则；`scope: raw` 表示未经处理的源码文本。注意 `scope: raw` 与规则中的 `raw:` 正则字段是两个不同概念。[existence 官方说明](https://docs.vale.sh/checks/existence)、[scope 官方说明](https://docs.vale.sh/topics/scopes)

### 4.3 候选正则与实现边界

建议分组识别 Windows 盘符、<!-- vale Wenlab.AbsolutePaths = NO -->`file://`<!-- vale Wenlab.AbsolutePaths = YES --> URI、UNC 路径以及以 `/` 开头的路径。下面是调查时的候选起点，不是最终配置；实施时按真实工具结果调整了边界条件，最终配置与实测覆盖边界见第 7 节：

```yaml
extends: existence
message: "发现绝对路径写法；项目文件请改用相对路径，必要的系统路径或教学反例需说明例外。"
level: error
scope: raw
ignorecase: true
nonword: true
tokens:
  - '(?:^|[\s\x60\x22\x27(<\[={])[A-Za-z]:[\\/]'
  - '\bfile://'
  - '(?:^|[\s\x60\x22\x27(<\[={])\\\\[^\\\s]+\\'
  - '(?:^|[\s\x60\x22\x27(<\[={])/[A-Za-z0-9_~.-]'
```

这些候选表达式只匹配具有路径特征的前缀，诊断重点是定位。中文标点紧邻路径、大小写、空格、转义、HTML 属性、URI 编码及各类 Markdown 包裹的行为不能由候选推定，实施时逐项实测，结果见 7.2 节。

不能把“全文匹配 `/…`”当成零误报方案：<!-- vale Wenlab.AbsolutePaths = NO -->`/help`<!-- vale Wenlab.AbsolutePaths = YES --> 可能是命令开关，`//cdn.example` 可能是网络地址，正斜线也可能出现在数学表达式或正则中。规则应通过上下文模式和局部例外处理这些情况，不通过全文件关闭来掩盖命中。

例外采用 Vale 控制注释的前提，是 3.24.0 在 `scope: raw` 下能可靠地定向禁用、恢复并给出准确的诊断行列；不满足时应改用经过验证的范围组合或局部豁免机制。实施时已验证该前提成立，例外语法与适用写法见 7.2 节。

正则检查不会解码所有 URI、规范化路径或解析环境变量，也不验证文件是否存在。“阻断常见绝对路径写法”与“穷尽所有绝对路径表示”应明确区分。

## 5. 启用 rumdl MD057

本次已查阅 rumdl **v0.3.0 标签下**的 MD057 文档：该版本文档包含相对文件链接检查和 `absolute-links = "warn"`。此前对版本兼容性的疑问，已补充版本文档依据；实施时已用 0.3.0 二进制回归，结果见 7.2 节。[v0.3.0 MD057 文档](https://github.com/rvben/rumdl/blob/v0.3.0/docs/md057.md)

修改 `.wenlab/rumdl.toml`：

1. 在现有 `[global].enable` 列表中增加 `"MD057"`，保留全部现有规则。
2. 增加以下配置：

```toml
[MD057]
absolute-links = "warn"
```

MD057 负责相对文件链接的存在性及文件名大小写，并对 `/` 开头的链接报警。它不检查正文路径说明或命令示例，不代替 Vale。项目已使用 `--fail-on any`，因此 MD057 告警会阻断 G1，也会随 G1 的检查进入 G2、G3。

Vale 路径规则在 G2、G3 执行，lychee 继续在 G2、G3 检查文件和锚点、在 G3 检查外部网站。根相对链接可能同时收到 Vale 和 MD057 告警；首版保留各自工具来源，不在编排层做易丢证据的合并。

外部项目可以通过现有 `rumdl.disable` 关闭 MD057。若未来需要保留存在性检查、仅放行发布站点的根相对路由，需另行设计配置能力；当前覆盖配置做不到这么细。新增 Vale 文件可由现有 `BasedOnStyles = Wenlab` 加载，不必为默认生效增加项目配置字段。

### 6.3 验证顺序

先为中文误报补充失败用例，确认现有规则会误报，再删除映射。随后独立验证路径候选和例外机制，验证 MD057，最后运行项目回归。

按仓库规定，修改规则配置后至少执行：

```powershell
pwsh -NoProfile -File ./tools/docs-audit/tests/Test-RealTools.ps1
pwsh -NoProfile -File ./tools/docs-audit/tests/Test-ReviewArtifacts.ps1
```

本次还应执行项目配置测试，确认关闭 MD057 的行为；如修改编排或 Gate，必须执行仓库规定的全部五个测试。文档修改后执行对应范围的 G1、G2，新增规则的教学反例先落实局部例外。G3 仅在发布前或明确要求联网检查时运行。

若 Gate 因缺工具或版本不符返回 2，按仓库规则记录工具、所需版本与错误后停止，不绕过版本要求。真实工具测试可能访问其用例所配置的 HTTP 服务，应按测试代码确认范围。

### 6.4 性能与完成标准

Vale 当前逐篇启动，新增规则不增加进程数量，但会增加每篇的规则加载和匹配工作；`scope: raw` 对全文处理，影响需要实测。用同一批小文件和长文档，对修改前后分别执行多次 `G2.ps1 -Profiler`，比较 Vale 的逐篇与总耗时，同时记录文件数、总字节数及告警数量。没有数据前不承诺固定百分比。

完成标准是：误导映射已移除；保留术语仍能检查；常见绝对路径按声明范围阻断；合法系统路径有可审计例外；MD057 在 G1 生效；文件、行列和规则名出现在诊断报告；源文件不被自动改写；规定回归通过。方案中列为待核验的覆盖边界必须在实施后更新为测试结果，不能直接当作已实现能力。
